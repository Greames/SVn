# 0006 — Netlify Preview Deploy Blocked with 403 Forbidden

- Status: Resolved (environment limitation, not fixable from here)
- Date raised: 2026-09-20
- Date resolved: 2026-09-21

## Question (original)

Can you check/fix one of the Netlify account settings below so a preview
deploy can go through? This is a one-off tooling blocker, not a business
decision — not related to `docs/decisions/0004-deployment-target-free-tier.md`
(production hosting is still separately undecided; this is just about
getting a throwaway preview link to verify the estimator prototype).

## Context

Asked to run the app and provide a URL to verify. This container can't
expose `localhost` to a browser directly, so with the business owner's OK
a Netlify site was created (`home-services-estimator-preview`, ID
`81732c29-0348-466e-ad1b-fd73e23d7e83`, team ID `6a77183fe6d60fb300772b39`)
to host a temporary preview.

## Root cause (confirmed)

**Not a Netlify account issue at all.** Two earlier theories — team SSO
enforcement, then Connected App OAuth scope — were both wrong and have
been ruled out.

The actual cause: this session's sandboxed network egress proxy blocks
_all_ outbound connections to `api.netlify.com` from anything run in its
shell (curl, `netlify-cli`, the `@netlify/mcp` CLI), regardless of
credentials. Confirmed directly:

```
curl -sS https://api.netlify.com/api/v1/user
→ curl: (56) CONNECT tunnel failed, response 403
```

and the proxy's own status endpoint logs the same rejection repeatedly:

```json
{
  "kind": "connect_rejected",
  "detail": "gateway answered 403 to CONNECT (policy denial or upstream failure)",
  "host": "api.netlify.com:443"
}
```

A Netlify Personal Access Token (generated by the business owner and
shared for this purpose, then advised to revoke afterward) also failed
identically — confirming it's not a credential/permission problem. The
only Netlify operations that work from this session are the built-in MCP
tool calls (e.g. creating the site succeeded), because those route
through Anthropic's own connector infrastructure, not this container's
network. The actual deploy/upload step needs a direct connection this
environment's policy doesn't allow.

## Outcome

No further account-side action needed — nothing was wrong on the Netlify
side. This is an infrastructure limitation of this particular sandboxed
session, not something fixable by changing any setting.

**For future preview needs:** either the business owner deploys from
their own machine (`pnpm build` with `output: "export"` temporarily set
in `next.config.ts`, then `netlify deploy --dir=out`), or verification
happens via screenshots taken by driving the app with a headless browser
inside this session (proven to work earlier — see the Electrical/
Painting/Summary tab screenshots sent 2026-09-19).
